Defeating Reverse Engineering: Java Bytecode Obfuscation & Keep Rules

SILENCE
October 15, 2026

Java's ubiquitous "Write Once, Run Anywhere" philosophy relies on bytecode (.class) maintaining rich symbolic metadata. From a software security standpoint, however, this transparency is a vulnerability. Without proactive hardening, proprietary algorithms, API endpoints, internal data structures, and cryptographic tokens are fully exposed to modern decompilers.

This engineering manual explains the bytecode obfuscation mechanisms deployed in Hera Klass and outlines Keep Rules patterns that prevent runtime collisions with reflection frameworks (Spring, Jackson, Fabric Mixin).

1. How Modern Decompilers Attack Bytecode

Modern Java decompilers (CFR, Procyon, Fernflower) reverse stack machine operations into Abstract Syntax Trees (ASTs) using a three-tier analysis pipeline:

  1. Control Flow Graph (CFG) Reconstruction: Parses conditional branch instructions (goto, if_icmpne) to rebuild structured loop constructs (for, while, try-catch).
  2. Type Inference Heuristics: Analyzes stack push/pop sequences to deduce local variable primitive and reference types.
  3. Constant Pool Dereferencing: Resolves UTF-8 entries referenced by LDC instructions to restore plain-text strings in-situ.

2. Hera Klass's Four-Stage Hardening Pipeline

Hera Klass disrupts AST generation heuristics directly within the bytecode:

[ Raw Compiled Bytecode ]
          │
          ├─► 1. Overload Collision: Reassigns identical alphanumeric symbols across varied method descriptors
          │
          ├─► 2. Control Flow Flattening: Rewrites sequential branches into monolithic switch state machines
          │
          ├─► 3. Opaque Predicates: Injects invariant mathematical conditions undecidable via static analysis
          │
          └─► 4. Dynamic String Decryption: Replaces string literals with XOR/AES payloads decrypted at runtime
          │
          ▼
[ Un-Decompilable Binary ]

Decompilers encountering this hardened bytecode crash via recursion timeouts, stack overflows, or output unreadable switch cascades.

3. Reflection-Safe Production Keep Rules (heraklass.pro)

Careless obfuscation breaks serialization libraries, causing ClassNotFoundException or JSON null mappings. The following template maintains runtime stability:

# 1. Preserve Application Entry Points
-keep class com.mycompany.app.Main {
    public static void main(java.lang.String[]);
}

# 2. Preserve Jackson / Gson Data Transfer Objects
-keep class com.mycompany.app.dto.** {
    <init>();
    get*();
    set*();
}

# 3. Preserve Framework Annotations (Spring / Fabric Mixin)
-keepclasseswithmembers class * {
    @org.springframework.web.bind.annotation.RequestMapping *;
    @org.spongepowered.asm.mixin.injection.Inject *;
}

# 4. Preserve Native JNI Bindings
-keepclasseswithmembernames class * {
    native <methods>;
}

4. Verification & Testing

Always execute Adversarial Verification on protected artifacts before release:

  1. Inspect the resulting .jar within CFR or JD-GUI to confirm sensitive algorithmic methods remain obscured.
  2. Run automated integration test suites (JUnit) to verify that JSON parsers and reflection boundaries execute without error.
