Hera Klass: Java 바이트코드 보호 및 난독화 아키텍처

Java 애플리케이션의 중간 언어인 바이트코드(Bytecode)는 고수준의 심볼릭 메타데이터(클래스명, 메서드 시그니처, 필드명, 디버그 라인 넘버)를 온전히 보존하는 구조적 특성을 지닙니다. 이로 인해 JD-GUI, CFR, Fernflower, Procyon과 같은 현대적인 디컴파일러 도구를 사용하면 수 초 만에 원본 소스코드로 역공학(Reverse Engineering)될 수 있습니다.

Hera Klass는 엔터프라이즈 데스크톱 소프트웨어와 상용 모드 애플리케이션의 지적 재산을 보호하기 위해 개발된 차세대 Java 바이트코드 보호 및 난독화 솔루션입니다.

1. 바이트코드 난독화 4대 핵심 변환 원리

Hera Klass는 OWASP Reverse Engineering 방어 가이드라인을 준수하며 다음과 같은 다계층 변환 파이프라인을 실행합니다:

[ 원본 Java JAR 파일 ]
          │
          ▼
[ ASM 바이트코드 파싱 및 클래스 그래프 구축 ]
          │
          ├─► 1단계: 식별자 리네이밍 (Unprintable Unicode / Overload Collision)
          │
          ├─► 2단계: 제어 흐름 평탄화 (Control Flow Flattening & Opaque Predicates)
          │
          ├─► 3단계: 다형성 문자열/상수 암호화 (Polymorphic AES/XOR Encryption)
          │
          └─► 4단계: 디버그 속성 소거 및 안티 디컴파일 트랩 삽입
          │
          ▼
[ 보호된 바이너리 패키징 및 무결성 서명 (Protected JAR) ]

A. 식별자 난독화 (Identifier Collision & Renaming)

클래스, 메서드, 필드명을 읽을 수 없는 유니코드 제어 문자나 마이크로소프트/리눅스 파일 시스템에서 허용되지 않는 특수 문자로 치환합니다. 또한 반환 타입과 파라미터가 다른 메서드들에 동일한 이름을 재할당하는 메서드 오버로드 충돌(Overload Collision) 기법을 적용하여 정적 분석 도구의 심볼 해석을 마비시킵니다.

B. 제어 흐름 평탄화 (Control Flow Flattening)

연속적인 if-else 및 루프 구조를 거대한 switch-case 블록과 가상 상태 머신(State Machine)으로 재구성합니다. 런타임에 항상 참(True) 또는 거짓(False)이 되지만 정적 분석기로는 결과를 예측할 수 없는 불투명 술어(Opaque Predicates)를 분기마다 삽입하여 디컴파일러의 제어 흐름 복원 알고리즘을 타임아웃 또는 스택 오버플로우로 유도합니다.

C. 동적 문자열 및 숫자 암호화 (Dynamic Constant Encryption)

소스코드 내의 모든 하드코딩된 문자열(API URL, 비밀 키, 데이터베이스 쿼리)과 숫자 상수를 암호화 배열로 변환합니다. 암호화 키는 단일 고정 키가 아니라 호출 스택의 해시값과 런타임 클래스로더 컨텍스트에서 유도되므로, 메모리 덤프나 바이트코드 역추적을 통한 평문 추출을 차단합니다.

2. 리플렉션 및 프레임워크 호환성을 위한 Keep Rules 문법

무분별한 난독화는 Spring, Jackson, Gson, Fabric Mixin과 같은 런타임 리플렉션 프레임워크에서 NoSuchMethodException 크래시를 유발합니다. Hera Klass는 정교한 정규표현식 기반의 제외 규칙(Keep Rules)을 제공합니다.

Keep Rules 설정 예시

# 1. 특정 패키지의 공용 API 엔드포인트 클래스 보존
-keep class net.silencehub.api.** {
    public *;
}

# 2. JSON 직렬화 대상 DTO 모델의 필드 및 기본 생성자 보존
-keep class net.silencehub.model.** {
    <fields>;
    <init>();
}

# 3. Fabric Mixin 어노테이션이 부착된 메서드 보존
-keepclassmembers class * {
    @org.spongepowered.asm.mixin.injection.Inject *;
    @org.spongepowered.asm.mixin.injection.ModifyVariable *;
}

# 4. Enum 열거형의 기본 values() 및 valueOf() 메서드 보존
-keepclassmembers enum * {
    public static **[] values();
    public static ** valueOf(java.lang.String);
}

3. GUI 및 CLI 통합 워크플로우

GUI 프로젝트 설정

  1. 프로젝트 열기: Hera Klass 실행 후 대상 JAR 파일을 드래그 앤 드롭합니다.
  2. 보호 프리셋 선택:
    • Lightweight: 성능 영향 0%, 기본 식별자 리네이밍 및 디버그 제거.
    • Standard (Recommended): 제어 흐름 평탄화 + 문자열 암호화 결합.
    • Maximum Security: 네이티브 호출 트랩 + 고강도 불투명 술어 적용.
  3. 라이브러리 경로 검증: 프로젝트가 참조하는 외부 라이브러리(lib/*.jar)를 등록하여 상속 관계 오판을 방지합니다.
  4. 빌드 실행: 'Build Protected JAR' 버튼을 클릭하면 수 초 내로 보호된 JAR 파일이 출력됩니다.

Gradle 빌드 파이프라인 자동화 (CLI)

CI/CD 파이프라인에서 Hera Klass를 자동 호출할 수 있습니다:

task obfuscateJar(type: Exec) {
    dependsOn jar
    commandLine 'java', '-jar', 'tools/heraklass-cli.jar',
        '--input', "${buildDir}/libs/app.jar",
        '--output', "${buildDir}/libs/app-protected.jar",
        '--rules', 'heraklass.rules',
        '--libraries', configurations.runtimeClasspath.asPath
}

4. 트러블슈팅 FAQ

Q1: 빌드 후 실행하면 ClassNotFoundException 또는 NoClassDefFoundError가 납니다.

원인: 외부 라이브러리가 사용하는 클래스명까지 리네이밍되었거나, 동적 리플렉션(Class.forName(...))으로 호출되는 클래스가 Keep Rules에서 누락된 경우입니다.
해결법: 리플렉션 대상 클래스를 -keep class com.example.MyService 형태로 규칙에 추가하세요.

Q2: 보호된 JAR 파일의 실행 속도가 느려졌습니다.

원인: 성능이 극도로 중요한 렌더링 루프나 빈번한 수학 계산 메서드에 '고강도 제어 흐름 평탄화(Aggressive Flattening)'가 적용되었을 때 발생합니다.
해결법: 핫스팟(Hotspot) 메서드를 규칙 파일에서 -noflatten class com.example.math.**로 제외하세요.

Q3: Minecraft 모드에 적용 시 Mixin 인젝션이 실패합니다.

원인: Mixin 메서드의 시그니처와 바닐라 타겟 메서드의 파라미터 매핑이 난독화 과정에서 틀어졌을 때 발생합니다.
해결법: Mixin 클래스는 항상 -keep 처리하고, 패치 대상 클래스의 멤버 시그니처를 보존하세요.
