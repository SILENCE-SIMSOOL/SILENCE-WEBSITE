커스텀 16x 리소스팩 제작 시 텍스처 깨짐 현상(CIT/OptiFine 대안) 해결 노하우

SILENCE
2026년 10월 20일

마인크래프트 리소스팩을 제작하거나 16x PvP/SkyBlock 텍스처팩을 현대적인 Fabric 환경으로 불러올 때, 보라색-검은색 체크무늬(Missing Texture)가 나타나거나 애니메이션 텍스처가 비정상적인 속도로 깜빡이는 현상을 흔히 목격할 수 있습니다.

이러한 문제의 90% 이상은 OptiFine의 독점적 CIT(Custom Item Textures) 포맷 의존성과 .mcmeta 메타데이터 구문 오류에서 기인합니다. 본 가이드에서는 텍스처 깨짐의 원인을 진단하고 현대 Fabric 생태계에 최적화된 리소스팩 빌드 노하우를 공유합니다.

1. 텍스처 깨짐의 3대 핵심 원인과 진단법

A. OptiFine 레거시 경로와 Modern 리소스팩 폴더 구조 불일치

  • 구버전 경로: assets/minecraft/mcpatcher/cit/...
  • 최신 표준 경로: assets/minecraft/optifine/cit/... 1.8.9 시절의 구형 리소스팩은 과거 'MCPatcher' 시절의 디렉터리 경로를 그대로 유지하고 있어, 현대적인 Fabric 로더에서는 텍스처 매핑을 전혀 인식하지 못하고 기본 텍스처로 대체됩니다.

B. .properties 파일 인코딩 및 구문 불일치

아이템 이름(Lore)이나 NBT 태그 기반으로 텍스처를 교체할 때 사용하는 .properties 파일이 UTF-8이 아닌 EUC-KR이나 ANSI로 저장되면, 한글이나 특수문자 인식에 실패하여 Missing Texture 체크무늬가 렌더링됩니다.

# 잘못된 예시 (ANSI 저장 시 한글 깨짐)
items=diamond_sword
nbt.display.Name=regex:.*심술의 검.*

# 올바른 해결책 (UTF-8 인코딩 보장 및 unifont 매핑)
items=diamond_sword
nbt.display.Name=regex:\u00a7[0-9a-fk-or]*.*심술의 검.*

C. MCMETA 프레임 속도와 보간(Interpolation) 오류

texture.png.mcmeta 파일에서 프레임 속도를 지정하지 않거나 텍스처 이미지의 세로 픽셀 비율(정사각형의 정수배)이 맞지 않으면 GPU 텍스처 아틀라스(Atlas) 생성 단계에서 텍스처 전체가 붕괴합니다.

2. Modern Fabric 생태계에서의 OptiFine 대체 모드 조합

OptiFine은 최신 Fabric 버전(1.21+)과의 호환성이 극도로 떨어지며 다른 모드와의 충돌을 유발합니다. 대신 아래의 오픈소스 모드 조합을 구성하는 것이 표준입니다:

기능 구형 OptiFine 현대 Fabric 권장 오픈소스 대체재
커스텀 아이템 텍스처 (CIT) 내장 OptiFine CIT CIT Resewn
커스텀 엔티티 모델 (CEM) 내장 OptiFine CEM Entity Model Features (EMF)
커스텀 엔티티 텍스처 Random Entities Entity Texture Features (ETF)
연결된 텍스처 (CTM) Connected Textures Continuity

3. 실전 리소스팩 검증 체크리스트

  1. 모든 .png 파일의 가로x세로 해상도가 정확히 $16 \times (16 \times N)$ 픽셀 규격을 만족하는지 확인합니다.
  2. 모든 텍스트 기반 메타데이터 파일(.json, .mcmeta, .properties)을 반드시 **UTF-8 (BOM 없음)**으로 인코딩합니다.
  3. SilenceUtils 및 LucentClient 환경에서는 자체 텍스처 캐시 검증기를 통해 누락된 텍스처가 감지될 경우 로그 파일에 파일 경로와 줄 번호를 즉시 보고해 주므로 빠른 디버깅이 가능합니다.
