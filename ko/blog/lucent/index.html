반복되는 모드 개발 비용, Lucent 아키텍처로 줄이기

SILENCE
2026년 10월 30일

마인크래프트 클라이언트 모드를 여러 개 개발하다 보면, 핵심 기능 구현보다 주변 인프라를 구축하고 유지보수하는 데 더 많은 시간을 쏟게 됩니다.

새 모드를 시작할 때마다 JSON 직렬화 로직과 설정 화면을 밑바닥부터 다시 구성해야 합니다. 여기에 마인크래프트 버전이 바뀌어 렌더링 파이프라인이 달라지면 기존 UI 코드가 작동하지 않는 문제도 자주 일어납니다.

모듈이 수십 개로 늘어나면 런타임 성능도 무시하기 어렵습니다. 화면에 상시 노출되는 여러 HUD가 매 프레임 벡터 연산을 수행하고, 사용하지 않는 이벤트 리스너가 매 틱마다 불필요하게 호출되며 프레임이 저하됩니다.

Lucent는 이러한 반복 작업을 줄이기 위해 설계된 Fabric 기반 코어 라이브러리입니다. Lucent가 렌더링 연산을 어떻게 줄이고, 설정과 프로필을 어떻게 격리했는지 내부 설계를 정리했습니다.

매 프레임 모든 HUD를 다시 그려야 할까요?

FPS 카운터, 플레이어 좌표, 키 스트로크처럼 항상 떠 있는 HUD는 인게임 화면에 흔히 존재합니다. 대다수 모드는 화면이 갱신될 때마다 배경 박스, 테두리, 그림자, 텍스트를 처음부터 다시 계산해서 그립니다.

하지만 플레이어가 가만히 서 있거나 HUD 텍스트가 직전 프레임과 똑같다면, 초당 수백 번씩 동일한 벡터 드로우를 반복할 필요가 없습니다.

Lucent는 최신 26.2 버전에서 Skia의 Java 바인딩인 Skija 기반 합성기를 도입하고, 이를 2단계 캐싱 파이프라인으로 구성했습니다.

Lucent 2단계 HUD 캐시 판단 흐름
Rendering Pipeline
1단계 · 전체 재사용
GPU 텍스처 즉시 복사
모든 활성 HUD의 캐시 키가 직전 프레임과 일치하면, Skia 드로우 과정을 생략하고 이전 GPU 텍스처를 그대로 블릿(Blit)합니다.
2단계 · 변경 없는 HUD
PictureRecorder 재생
일부 HUD의 내용만 바뀌었다면, 변경되지 않은 나머지 HUD는 미리 녹화된 Skia 명령(Picture)을 그대로 재생해 레이아웃 연산을 건너뜁니다.
3단계 · 변경된 요소만
선택적 벡터 렌더링
데이터가 실제로 바뀐 HUD만 Skia 캔버스에서 새로 그립니다. 5초 이상 쓰이지 않는 오프스크린 타겟은 VRAM에서 자동 해제됩니다.

개발자는 HUD 클래스에서 렌더링 결과에 영향을 주는 값만 캐시 키로 반환하면 됩니다.

@Override
public Object getRenderCacheKey() {
	// 반환한 값이 변경될 때만 HUD를 다시 그립니다.
	return List.of(mc.getFps(), mc.player.position());
}

HUD 매니저는 이 키에 좌표, 배율, 정렬 기준, 해상도를 결합해 프레임 해시를 생성합니다. 값이 유지되는 동안에는 벡터 드로우 호출 자체가 발생하지 않으므로, 여러 HUD를 띄워도 프레임 드랍이 일어나지 않습니다.

OpenGL과 Vulkan 지원과 JAR 파일 크기 관리

마인크래프트의 렌더링 환경은 전통적인 OpenGL 외에도 Vulkan 백엔드를 도입하는 형태로 변화하고 있습니다.

하지만 Skia 같은 네이티브 그래픽 엔진을 사용하려면 윈도우, 맥, 리눅스 및 CPU 아키텍처별 바이너리가 필요합니다. 이를 모드 JAR 안에 전부 포함하면 파일 크기가 수십 MB로 커져 배포에 비효율적입니다.

Lucent는 런타임 환경 감지와 온디맨드 네이티브 프로비저닝을 통해 이 문제를 처리합니다.

그래픽 백엔드 분기 및 네이티브 로더 구조
Dual Backend
런타임 백엔드 감지
OpenGL 및 Vulkan 자동 대응
현재 렌더 장치를 판별하여 OpenGL 환경에서는 상태 백업 가드(GlStateGuard)로 마인크래프트 GL 상태 오염을 방지하고, Vulkan 환경에서는 프레임 배리어로 텍스처를 안전하게 공유합니다.
경량 모드 배포
첫 실행 시 1회 백그라운드 다운로드
모드 JAR 안에는 네이티브 바이너리를 탑재하지 않습니다. 첫 실행 시 데몬 스레드가 사용자의 OS와 CPU 아키텍처에 맞는 Skia 라이브러리만 Maven Central에서 내려받아 로컬 캐시에 저장합니다.

모드 배포 파일은 가볍게 유지되면서, 사용자의 환경에 맞는 네이티브 라이브러리가 첫 실행 시 자동으로 준비됩니다.

60개가 넘는 이벤트 중 필요한 것만 연결하기

클라이언트 모드는 틱, 패킷 송수신, 채팅, 월드 렌더링, 블록 상호작용 등 다양한 이벤트를 처리합니다. Lucent의 기본 Mod 클래스에도 60개가 넘는 이벤트 훅이 정의되어 있습니다.

모듈이 50개일 때 매 틱마다 50개 모듈을 전부 순회하며 빈 메서드를 호출하면 불필요한 가상 함수 호출이 반복됩니다.

Lucent는 모듈이 등록되는 시점에 리플렉션을 사용하여 개발자가 실제로 오버라이드한 메서드만 식별하고 이벤트 버스에 등록합니다.

전체 모듈 순회 vs 선택적 이벤트 바인딩
Event Architecture
전체 순회 방식
모든 이벤트마다 전체 모듈 호출
60개 이벤트 × 50개 모듈 구조에서는 구현되지 않은 빈 메서드까지 매번 호출되어 CPU 캐시 효율이 떨어집니다.
Lucent 방식
오버라이드된 훅만 버스에 연결
시작 시 getDeclaringClass() != Mod.class 여부를 확인하여, 실제로 코드가 작성된 이벤트에만 리스너를 등록합니다.

또한 매 틱마다 실행할 필요가 없는 로직을 위해 틱 주기를 네 단계로 분리했습니다.

  • onTick (1틱): 매 틱마다 실행해야 하는 실시간 처리
  • onMediumTick (5틱): 짧은 주기의 상태 확인
  • onHighTick (10틱): 주기적인 주변 엔티티 탐색
  • onEverySecond (20틱): 1초 주기의 통계 및 타이머

주기적인 로직을 알맞은 틱 메서드로 분리하는 것만으로도 이벤트 연산 빈도를 크게 낮출 수 있습니다.

어노테이션 기반 설정과 프로필 관리

설정 화면 UI를 만들고 JSON 직렬화를 연결하는 과정은 모드 개발에서 많은 비중을 차지합니다. Lucent에서는 필드에 @ModConfig 어노테이션을 선언하는 것만으로 설정 화면과 JSON 저장이 자동으로 구성됩니다.

@ModConfig.CategoryPriority(name = "General", priority = 1000)
public class ExampleMod extends Mod {

	@ModConfig(
		type = ConfigType.SWITCH,
		name = "하이라이트 활성화",
		description = "바라보는 블록 외곽선을 강조 표시합니다."
	)
	public static boolean useHighlight = false;

	@ModConfig(
		type = ConfigType.COLOR,
		name = "하이라이트 색상",
		parent = "useHighlight"
	)
	public static Color highlightColor = new Color(85, 255, 85, 255);
}

parent 속성을 사용하면 상위 옵션이 활성화되었을 때만 하위 설정이 화면에 노출되는 계층 구조를 간단히 만들 수 있습니다.

설정 저장 경로를 OS 사용자 데이터 폴더로 잡은 이유

일반적인 모드들은 설정을 .minecraft/config 폴더에 저장합니다. 하지만 멀티 인스턴스 런처를 사용하거나 마인크래프트 새 버전을 설치할 경우, 이전 인스턴스에서 설정한 HUD 위치와 단축키를 매번 다시 설정해야 하는 불편함이 있습니다.

Lucent는 설정을 마인크래프트 인스턴스 폴더가 아닌 OS의 사용자 데이터 경로(Windows 기준 %APPDATA%/Lucent)에 보관합니다.

OS 레벨 프로필 격리 및 인스턴스 간 공유 구조
Storage Design
전역 환경 설정
lucent_global.json
현재 프로필, 테마, UI 배율, 배경 블러, 언어 설정을 인스턴스와 무관하게 중앙에서 관리합니다.
모드별 격리 폴더
config/<mod_id>/profiles/
모드별 설정값(config.json)과 HUD 위치·정렬(hud.json)을 프로필 단위로 분리하여 모드 간 충돌을 방지합니다.
인스턴스 무손실 유지

새로운 마인크래프트 인스턴스를 생성하더라도 별도의 파일 복사 없이 기존에 설정한 모든 HUD와 프로필이 유지됩니다.

모드 프로젝트에 Lucent 연동하기

LucentAPI 진입점을 사용하면 외부 모드에서도 몇 줄의 코드로 설정 매니저와 HUD를 등록할 수 있습니다.

public class MyClientMod implements ClientModInitializer {
	public static final ModManager CONFIG = LucentAPI.createModManager("mymod");

	@Override
	public void onInitializeClient() {
		CONFIG.register(new ExampleMod());
		LucentAPI.registerHUD(CONFIG, new ExampleHUD());
	}
}

다국어 리소스 역시 모드 JAR의 assets/<modid>/lucent/lang/ 폴더에 번역 파일을 포함하면 실행 시 자동으로 로드되어 병합됩니다.

반복되는 인프라 작업을 줄이고 모드의 핵심 기능에 집중할 수 있는 환경을 제공하는 것이 Lucent의 목적입니다. 전체 소스코드는 Lucent GitHub 저장소에서 확인할 수 있습니다.
