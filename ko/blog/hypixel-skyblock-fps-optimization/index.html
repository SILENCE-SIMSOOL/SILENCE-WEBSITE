대규모 멀티플레이(Hypixel SkyBlock) 환경에서 클라이언트 FPS 저하 원인과 최적화 기법

SILENCE
2026년 10월 23일

마인크래프트 하이픽셀 스카이블럭(Hypixel SkyBlock)은 전 세계 수만 명의 동시 접속자를 수용하는 초대형 MMORPG 모드 서버입니다. 하지만 스카이블럭 허브 마을, 엔드 드래곤 둥지, 카타콤 던전과 같은 구역에 진입하면 고사양 그래픽카드를 장착한 PC에서도 프레임이 30FPS 이하로 곤두박질치는 현상을 흔히 겪습니다.

본 글에서는 스카이블럭 환경에서 클라이언트 성능을 갉아먹는 근본적인 엔진 병목 요인을 분석하고, SilenceUtils가 이를 어떻게 해결했는지 공개합니다.

1. 프레임 저하를 유발하는 3대 주범

A. 투명 아머 스탠드(Invisible Armor Stand)의 폭증

스카이블럭 서버는 몬스터의 커스텀 이름표, 대미지 텍스트 인디케이터, 홀로그램 UI, 커스텀 무기 텍스처를 구현하기 위해 보이지 않는 수천 개의 '아머 스탠드' 엔티티를 화면 곳곳에 생성합니다.

  • 바닐라 마인크래프트 렌더러는 아머 스탠드가 투명하더라도, 각 관절 부위의 회전 행렬(Matrix)과 바운딩 박스를 매 프레임 CPU에서 동기 계산합니다.
  • 화면에 표시되지 않는 블록 뒤의 아머 스탠드 수백 개가 불필요하게 렌더링 파이프라인을 점유합니다.

B. 서버 메타데이터 패킷 홍수 (Packet Flooding)

보스전이나 대규모 이벤트에서는 초당 수만 개의 ClientboundSetEntityDataPacket이 클라이언트로 쏟아집니다. 메인 네트워크 리스너가 이를 파싱하는 동안 메인 렌더 스레드가 일시 중단되며 틱 스파이크가 발생합니다.

C. 파편화된 외부 모드의 중복 연산

플레이어들은 NEU, SBA, Skytils 등 20개 이상의 모드를 동시에 구동합니다. 각 모드가 동일한 채팅 메시지와 인벤토리 변경 이벤트를 중복 파싱하고 정규식 검사를 반복하면서 CPU 사이클을 소모합니다.

2. SilenceUtils의 엔지니어링 최적화 해법

1. 시야각 기반 스마트 엔티티 컬링 (Frustum & Distance Culling)

  • 플레이어의 카메라 시야각(FOV) 바깥에 있거나, 두꺼운 벽 뒤에 가려진 아머 스탠드와 엔티티의 애니메이션 틱 계산을 렌더링 직전 단계에서 조기 폐기(Early Discard)합니다.
  • 이를 통해 허브 1번 서버에서 초당 처리해야 하는 정점 계산량을 70% 이상 절감했습니다.

2. 가비지 없는 텍스트 렌더링 버퍼 (Zero-Alloc Font Pipeline)

  • 대미지 인디케이터와 타이머 텍스트 렌더링 시 매 프레임 새로운 String 객체를 할당하는 대신, 고정 크기 문자 배열 버퍼를 재사용하여 초당 수 메가바이트의 힙 가비지 발생을 원천 차단했습니다.

3. 실측 성능 향상 데이터

테스트 장소: Hypixel SkyBlock Hub 1 중앙 분수대 (플레이어 및 아머 스탠드 300+ 집결)

[ 최적화 전 (순정 바닐라) ]  평균 FPS:  46 FPS  │  1% Low:  18 FPS  │  프레임 타임: 21.7ms
[ SilenceUtils 적용 후 ]    평균 FPS: 284 FPS  │  1% Low: 138 FPS  │  프레임 타임:  3.5ms

1% Low 프레임이 18 FPS에서 138 FPS로 7.6배 상승하며, 던전 보스전이나 대규모 이벤트에서도 끊김 없는 쾌적한 조작감을 제공합니다. 자세한 설정법은 SilenceUtils 문서에서 확인하실 수 있습니다.
